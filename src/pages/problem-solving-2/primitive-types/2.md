We need to find the parity of a given number. Specifically a 64 bit integer. Here, we look at **Odd Parity**, which becomes `true` if the number of `1`s in the binary representation of the number is **Odd**, and is `false` otherwise.

A brute force solution to this might look as follows:
```java
// Java

public static boolean getParity(long x) {
    boolean result = false;

    while(x != 0) {
        if(x & 1) result != result;
        x >>> 1;
    }

    return result;
}
```

In this method, we start by assuming the number is not of odd parity, and everytime we enounter a `1` in the number, we flip the truth value. So, if the number really was of odd parity, an odd number of flips to `result` would return `true`, and an even number of flips to `result` would return `false`.

Now the time complexity of this brute force approach would be `O(n)` where `n` is the total number of bits in the number `x`.

To understand how this can be optimized further, consider the number `2^64`. This number in binary only has a `1` at the `64th` position or the **MSB**. Which means our brute force solution would have to do 64 iterations, all for the sake of a single bit sitting at position 64.

This leads to the idea of erasing the left most 1. Consider the 5-bit number `10100`. The **Left Most** `1` is the `1` at position 3 (counted from the right, 1 indexed). That particular bit can be erased (set to 0) in a single operation => `x & (x-1)`.

How ? I urge you to read the <a href="https://www.amazon.in/Elements-Programming-Interviews-Java-Insiders/dp/1517671272" class="underline" target="_blank">book</a>. The content I write serves as last minute revision, not the whole book's explanation.

So in `10100`, erasing the right most `1` gives `10000`, and doing it one more time gives `0` at which point our loop can end. We calculated the parity in `2` iterations, not `5`. Good.

So, employing that trick, we get
```java
public static boolean getParity(long x) {
    boolean res = false;

    while(x != 0) {
        // Erase the rightmost 1
        x = x & (x-1);
        res != res;
    }

    return res;
}
```

- The time complexity of this would be `O(k)` where `k` is the number of high bits.
The worst case for this is when all bits are `1`, when it would still end up doing `O(n)` iterations.

- The next optimization is using **Divide and Conquer**. It involves the realization that the parity of any binary number is simply the **XOR of all bits** in the number. (Odd Parity).

XOR being associative and Commutative, means we can apply the operation in any order with any form of grouping. So to do this, we break down our 64-bit number by 2 each time until we have 1 bit.

Basically, we start by cutting our 64-bit number into two 32-bit halves and XOR them. Then we cut the 32 bit number into 2 16-bit numbers and XOR them, until we are left with a single bit.

```java
public static boolean getParity(long x) {
    // x is a 64 bit number;

    for(int i=32; i >= 1; i/=2) {
        x = x ^ (x >>> i);
    }

    return (x & 0x1) == 1;
}
````
